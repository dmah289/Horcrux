Cách dùng

Trước khi chạy

Dựng từ 0 theo thứ tự; mỗi bước kèm chỗ hỏng nếu thiếu. BootstrapService dựng theo Bootstrap.md, TimeService theo TimeSystem.md.

1. Host

  1. Tạo GameObject con của GameObject BootstrapService, Add Component LiveOpsHost và LiveOpsHostInitializer.
  2. Trên LiveOpsHostInitializer, ô Time Service để Service.
  3. Ô Order của LiveOpsHost lớn hơn Order của SaveBootstep.
  4. Kéo LiveOpsHost vào ô Steps của BootstrapService.
ThiếuHỏng ở đâu
LiveOpsHostInitializerInit không được gọi, timeService là null: NRE ở dòng now đầu tiên của RunAsync, trong chuỗi boot, nơi .Forget() chỉ để lại một dòng đỏ. Chuỗi boot vẫn chạy tiếp; host chết cả phiên
TimeService trong scenenhư trên — ô Time Service không có gì để nhận
LiveOpsHost trong StepsInitializeAsync không chạy → không module nào Initialize, không tick, widget im lặng không hiện
Order sau SaveBootstepmodule Initialize trên save chưa load: Refresh đọc giá trị mặc định — rollover và State sai
FindFromScene thấy được scene chứa host — scene nạp bằng Addressables là nạp sau khi InitArgs khởi tạoServiceInjector chỉ LogWarning "Service Not Found" rồi trả null; ILiveOpsHost.Service và ô Init để Service ném NRE ở caller đầu
BootstrapService được game gọi InitializeAsync() (Bootstrap.md › Trước khi chạy)không step nào chạy: save không load, host không Initialize, không tick

2. Module

  1. Viết class kế thừa ALiveOpsModule (mẫu bên dưới) và một *Initializer cho nó, trong đó có ô ILiveOpsHost.
  2. Add Component module vào GameObject đang active trong scene sống suốt phiên, cùng đúng một Initializer của module; ô Target trỏ vào module, ô ILiveOpsHost để Service.
ThiếuHỏng ở đâu
Initializer, hoặc ô ILiveOpsHost trốngLiveOpsHost của module null → NRE ở Start, không một dòng log trước đó
GameObject activeStart chưa chạy → chưa Register → module không bao giờ Initialize, State mãi Inactive
Initializer thừa với Target trốngInitArgs AddComponent một module thứ hai lúc Awake; nó đăng ký host trước bản trong scene và không ai cấu hình nó. Đã sai một lần: lộ bằng NRE trong Refresh của module có GetInstanceID() âm
base.Start() / base.OnDestroy() khi overridethiếu base.Start() → không Register, như GameObject inactive · thiếu base.OnDestroy() → Modules giữ module đã destroy; host vẫn tick nó, Refresh chạm API Unity thì MissingReferenceException mỗi giây

3. Mất tiến độ khi thua (tuỳ chọn)

  1. Module có tiến độ mất được khi thua: viết class kế thừa ALiveOpsLoseFlow (mẫu bên dưới), tạo nó trong Init của module và trả về qua LoseFlow.
  2. Cờ HasPendingLoss nằm trong save của module và ghi xuống đĩa ngay trong setter.
  3. Refresh xoá cờ khi sang chu kỳ mới.
  4. Một cầu nối của dự án báo sự kiện level vào LiveOpsLossHelper:
public sealed class LoseFlowBridge : MonoBehaviour
{
    [SerializeField] private LiveOpsHost liveOpsHost;

    // Gọi từ luồng level của game.
    public void OnReviveOffered() => LiveOpsLossHelper.BeginPendingLoss(liveOpsHost.Modules);
    public void OnRevived() => LiveOpsLossHelper.CancelPendingLoss(liveOpsHost.Modules);
    public void OnLevelLost() => LiveOpsLossHelper.CommitLoss(liveOpsHost.Modules);
    // Bỏ level giữa chừng có tính là thua không là luật của game.
    public void OnLevelAbandoned() => LiveOpsLossHelper.CommitLoss(liveOpsHost.Modules);
}

Ghi cờ ngaykill app khi popup hồi sinh đang mở → cờ chưa xuống đĩa → lần boot sau không áp mất: người chơi thoát app để né thua
Xoá cờ khi sang chu kỳcờ cũ sống qua chu kỳ mới → Initialize áp mất lên tiến độ chu kỳ mới

Viết một module

public sealed class MyEventModule : ALiveOpsModule, IInitializable<ILiveOpsHost, IMySaveData>
{
    [SerializeField] private string moduleId = "my_event";
    [SerializeField] private Sprite lossIcon;

    private ILiveOpsHost liveOpsHost;
    private PersistenceDataEntry<MyEventSave> entry;
    private MyLoseFlow loseFlow;

    protected override ILiveOpsHost LiveOpsHost => liveOpsHost;
    public override string ModuleId => moduleId;
    public override ALiveOpsLoseFlow LoseFlow => loseFlow;

    public void Init(ILiveOpsHost host, IMySaveData save)
    {
        liveOpsHost = host;
        entry = save.MyEvent;                                // PersistenceDataEntry<MyEventSave>
        loseFlow = new MyLoseFlow(this, entry, lossIcon);    // trước Start: Initialize cần nó
    }

    protected override LiveOpsWindow ResolveWindow(long nowUnix)
        => WeeklySchedule.Resolve(nowUnix, 1, 8, 1, 604740); // Thứ Hai 08:01 UTC, 7 ngày − 60 s

    protected override void Refresh(long nowUnix)
    {
        if (entry.Value.cycleStartUnix != Window.StartUnix)  // chu kỳ mới
        {
            entry.Value.cycleStartUnix = Window.StartUnix;
            entry.Value.progress = 0;
            entry.Value.hasPendingLoss = false;
        }

        SetState(Window.Contains(nowUnix) ? LiveOpsModuleState.Running : LiveOpsModuleState.Inactive);
    }
}

anchorDayOfWeek theo System.DayOfWeek: Sunday 0 … Saturday 6. Monday 08:01 là (1, 8, 1).

Viết lose flow

public sealed class MyLoseFlow : ALiveOpsLoseFlow
{
    private readonly MyEventModule module;
    private readonly PersistenceDataEntry<MyEventSave> entry;
    private readonly Sprite icon;

    public MyLoseFlow(MyEventModule module, PersistenceDataEntry<MyEventSave> entry, Sprite icon)
    {
        this.module = module;
        this.entry = entry;
        this.icon = icon;
    }

    public override bool IsProgressAtStake => module.State == LiveOpsModuleState.Running && entry.Value.progress > 0;
    public override LiveOpsLossWarning Warning => new(icon, $"x{entry.Value.progress}", "You will lose your event progress!");

    protected override bool HasPendingLoss
    {
        get => entry.Value.hasPendingLoss;
        set
        {
            entry.Value.hasPendingLoss = value;
            entry.FlushNow();                                  // ghi ngay: kill app không được mất cờ
        }
    }

    protected override void ApplyLoss() => entry.Value.progress = 0;   // phải để IsProgressAtStake = false
}

LiveOpsLossWarning(Icon, Badge, SingleWarningDesc): Badge rỗng thì ẩn nhãn badge; SingleWarningDesc dùng khi chỉ một live-ops bị đe doạ.

Hợp đồng của module

LuậtVì
Refresh không tự tính cửa sổ — ResolveWindow trả, base gán WindowSecondsLeft đọc Window; Refresh quên gán thì countdown đứng 0m 0s cả phiên, không lỗi nào nổ. Tách ra thì không trả về là không biên dịch được

Không Unregister hay DestroyImmediate một module trong Tickhost lặp theo index: bỏ phần tử giữa vòng thì module kế bị bỏ qua tick đó. Destroy thường chạy cuối frame, an toàn
